# Configuration

lain needs no config file before the first run, and every setting here has a working default.
Project settings live under `.lain/` in the project, your own settings in
`$XDG_CONFIG_HOME/lain/config.rb`, and a few defaults come from the environment.
[`examples/`](../../examples/) has files you can copy.


## Project files

These are project artifacts, like `.git/`, not XDG state.

| Path | What it holds |
|---|---|
| `.lain/slots/*.md` | Prompt slot fills. What lands in the system prompt for this project. |
| `.lain/slots/role/*.md` | Per-role prompt fills, over the shipped role templates. `auto_approver.md`, `gate_adjudicator.md` and `evidence_researcher.md` are refused at launch: those roles decide approvals, and a project must not rewrite the prompt that judges its own calls. A project's `system.md` fill still reaches every role, these included. |
| `.lain/slots/skill/<skill>/<hole>.md` | Per-skill prompt fills, one file per hole. |
| `.lain/skills/<name>/skill.md` | Your skills, merged over the shipped catalog. Reachable as `@role/skill` at the prompt. |
| `.lain/config.rb` | Your per-project settings. See [Project config](#project-config). |
| `.lain/services.rb` | The isolation services DSL: the per-worker `postgres` databases and `compose` stacks a worker's lease provisions. Read by the `DbIndex` and `Compose` decorators, which layer over whatever `--isolation` resolved. |
| `.lain/summarizers.rb` | Your deterministic tier-0 summarizers, tried before any model call. See [Compaction and summarizer tiers](compaction.md). |
| `.lain/summarizers/` | Drafts written by `/meta summarizer`, for you to read and copy into `summarizers.rb`. Nothing loads this directory. |
| `.lain/meta/` | Scripts generated by [`/meta`](commands.md#meta). |

## Trust

Ruby you write runs only after you trust it. `.lain/config.rb`, `.lain/services.rb` and
`.lain/summarizers.rb` are evaluated as Ruby. A launch that finds any top-level `.lain/*.rb`
untrusted, or a `config.rb` that will not load, is refused before anything starts; the message
names the file and line, and for an untrusted file it names [`lain trust`](commands.md#lain-trust).
Trust covers the top-level `.lain/*.rb` files only, not the files they `require` or `load`, and is
keyed on the project root and those bytes: a changed byte, or the same files under another root,
needs a new decision, while a linked worktree that inherits the main checkout's `.lain/` shares it.
Your user-level `$XDG_CONFIG_HOME/lain/config.rb`, which may declare `middleware` for every project,
is trusted separately with `lain trust --user`; see [User config](#user-config).

## State paths

`Lain::Paths` resolves `$XDG_STATE_HOME` (falling back to
`~/.local/state`), `$XDG_CONFIG_HOME`, `$XDG_CACHE_HOME`, and `$XDG_RUNTIME_DIR`. A non-absolute
`$XDG_*` value is invalid per the spec and is ignored, so the `$HOME` fallback takes over.

`$HOME` itself must be absolute, and lain refuses to start if it is not. Every fallback above
is built on it, and a relative `$HOME` makes every one of those paths relative. They then resolve
against whatever directory you happen to be in, which writes lain's machine state into your
project. There is nothing to fall back to, so lain says so and stops.

| Path | What it holds |
|---|---|
| `$XDG_STATE_HOME/lain/sessions/<project-hash>/` | Session NDJSON and its `.wal`. One directory per project. |
| `$XDG_STATE_HOME/lain/improvements.ndjson` | The cross-project dogfood queue. |
| `$XDG_STATE_HOME/lain/history` | The TTY prompt's history. |
| `$XDG_STATE_HOME/lain/status/<project-hash>/state.json` | The status HUD's state, read by the tmux and nvim plugins. Rewritten every turn, which makes it machine state and not a project artifact. |

## Environment

| Var | Read by | Meaning |
|---|---|---|
| `ANTHROPIC_API_KEY` | `Provider::Anthropic` | Required for the Claude path. Refused before construction if unset. |
| `OLLAMA_API_KEY` | `Provider::Ollama` on its cloud deployment | Required for `--provider ollama-cloud`. Create one at [ollama.com/settings/keys](https://ollama.com/settings/keys). Refused before construction if unset, and the refusal names the variable without quoting its value. Four guards (`#inspect`, `#pretty_print`, and both `#instance_variables`) keep the key out of a rendered deployment or configuration; they do not cover a header Hash once it has left the object, which is documented where that Hash is built. |
| `LAIN_PROVIDER_CONCURRENCY` | the admission gate, every provider | How many requests may be in flight to one endpoint; `0` removes the limit. Unset, a local ollama runs 1 at a time and ollama cloud runs 3; a typo raises rather than degrading. A concurrency 429 from the server narrows the width to the plan's limit for the rest of the process (see [Providers](providers/README.md#providers)), and a cloud launch prints the width at startup. |
| `LAIN_PROVIDER`, `LAIN_MODEL`, `LAIN_API_BASE`, `LAIN_NUM_CTX`, `LAIN_NUM_BATCH` | `lain chat` and the other commands taking the run-profile flags | Defaults for `--provider`, `--model`, `--api-base`, `--num-ctx` and `--num-batch`, so a project can pin them in a direnv `.envrc`. A typed flag wins, a malformed number refuses by name, and an empty variable counts as unset. |
| `LAIN_STREAM_STALL_TIMEOUT` | the provider's stall watch | Seconds of silence on an open stream before lain reports `stalled_stream` and stops. Defaults to 30, except on `--provider ollama` and `ollama-cloud`, which default to 5 seconds under their request timeout: 295 for a local ollama (request timeout 300) and 115 for ollama cloud (120). Ollama sends a tool call's arguments whole, after a silence that grows with their size, so a long `epic_write` needs the room. A set variable wins on every provider, and `0` turns the check off. A stalled ask names this variable in the message that ends it. |
| `LAIN_CONNECT_TIMEOUT` | the provider's connect watch | Seconds to wait for a connection before giving up; defaults to 5, and `0` folds connect time back into the request timeout. |
| `LAIN_STREAM_DEBUG` | the SSE engine | Dumps raw stream frames while debugging a provider. |
| `LAIN_INTEGRATION`, `LAIN_OLLAMA`, `LAIN_OLLAMA_CLOUD`, `LAIN_SPIKE` | the test suite | Opt in to the specs that cost money, need a local Ollama, spend Ollama Cloud quota, or run a spike. |

The library does not read `OLLAMA_API_BASE`. The Ollama base is a constructor argument or the
`--api-base` flag; the env var is a convenience for the specs only. `OLLAMA_API_KEY` is the
exception: the cloud deployment reads it, because a flag should not carry a key.
Everything else, sampling and summarizer settings included, is a CLI flag, documented in [`docs/users/commands.md`](commands.md).

## Project config

`.lain/config.rb` is Ruby, evaluated once per launch, with 14 verbs. Each verb may appear once, and
every one is optional. Each is read by its own strict reader: an unknown key is refused by name,
listing the keys that do exist, because a restricting table has to refuse a typo loudly and
cannot silently leave the restriction off.

The file runs only after [`lain trust`](commands.md#lain-trust) has recorded its bytes. A file that exists and
is untrusted, or that will not load (a Ruby error, an unknown verb, a refused value), refuses every
launch before anything starts, naming `.lain/config.rb:LINE`. A project with no `.lain/config.rb`
is never refused: every table is then at its default. A verb that belongs in the user's file is refused
in this one, naming the user's config.rb.

| Verb | What it sets | File |
|---|---|---|
| [`epics`](#epics) | Where epics live, how many run at once, and each stage's gate. | project |
| [`approval`](#approval) | Allow and deny rules, wait timeouts and the judge memo. | project |
| [`isolation`](#isolation) | How a worker's checkout is kept, brought current and merged. | project |
| [`sensitivity`](#sensitivity) | Path rules and related directories for secrets. | project |
| [`shell`](#shell) | Programs the shell tool refuses. | project |
| [`search`](#search) | How `grep`, `glob`, `list_files` and `ast_search` walk the project. | project |
| [`tests`](#tests) | The project's test layout. | project |
| [`env`](#env) | Environment variables handed to every bash command. | project |
| [`todos`](#todos) | The name of the chore file. | project |
| [`think`](#think) | The reasoning level a chat asks for. | project |
| [`review`](#review) | The model a document review runs under. | project |
| [`budget`](#budget) | Iteration limits by skill or role. | project |
| [`middleware`](#middleware) | Your own code, run around what lain does. | project and user |
| [`github`](#github) | The GitHub account and the review queue's filters. | project and user |

```ruby
epics home: :repo, width: 3 do
  gate :research, :hands_off
end
approval timeout: 900, judge_timeout: 60, silence: :hold, judge_memo: true do   # judge_timeout is the auto judge's own limit; 30 when unset
  allow "bash", command: "bundle exec rspec"
  deny_tool "web_fetch"                         # refuses the tool whatever its tier; no approval lifts it
end
isolation retain_days: 14
sensitivity gated: %w[secrets.yml], related: %w[~/notes]
shell exclude: %w[curl]                         # bash commands only
search include: %w[planning/notes/*.md], max_entries: 50_000, max_bytes: 100_000_000
tests preset: :rspec
```

### epics

`home:` is `:xdg` by default, or `:repo` to keep epics under `.lain/epics/`. `width:` sets how many run
at once. The block takes one `gate stage, policy` line per stage.

### approval

`allow "tool", field: value` and `deny "tool", field: value` match one tool call by
input; `deny_tool "tool"` refuses a whole tool and takes no fields.

* `timeout:` is how many seconds a parked call waits for an answer before it is denied (300 by
  default). It must be a finite number above 0, and the prompt, `lain://approval` and the chat
  show the time left. It also bounds how long an interactive epic gate waits for a sign-off.
* `silence:` is what a wait nobody answered settles as, for a parked call and an epic gate alike:
  `:hold` (the default) or `:deny`. Anything else is refused by name.
  * Under `:hold` a parked call is postponed, leaving the queue until the agent issues it again.
    A silent gate is held and listed for you while the agent tells you. The prompt warns
    `postpones`.
  * Under `:deny` both are denied as before (`auto-denies`), for an unattended run that should
    fail closed.
  * A Ctrl-C or other cancelled wait is not silence and denies whatever the rule.
* `judge_memo:` is `true` (the default) or `false`. Anything else is refused by name. While it is
  on, a call the `auto` judge approved is approved again without asking the judge when the same
  tool, input, requester, cwd, path classifications and facts come back in the same session. The
  record's reason is "the judge approved this exact call earlier this session", and the
  transcript shows a dim line, `the judge approved this earlier: tool(input)`. A deny, a
  deferral or a judge fault is never remembered, so such a call asks the judge again.

### isolation

How a worker's checkout is kept, brought current, and merged. Every key has a default, so the
table is optional and an absent one behaves exactly like the defaults below.

| Key | Default | What it does |
|---|---|---|
| `retain_days` | `7` | Days a released worktree is kept before [`lain worktrees gc`](commands.md#lain-worktrees-gc) may reap it. A whole number of days, at least 1. |
| `rebase_retries` | `1` | How many times a worker retries its self-rebase before handing back. At least 0; `0` is how a project turns worker self-sync off entirely. |
| `diff_algorithm` | `histogram` | `histogram`, `patience`, `minimal`, or `myers`. Reaches git as `-X diff-algorithm=<value>`. |
| `conflict_style` | `zdiff3` | `zdiff3`, `diff3`, or `merge`. Reaches git as `-c merge.conflictStyle=<value>`. |
| `verifier` | `command` | The strategy that judges a landing batch. Only `command` exists. |
| `verify` | `[]` | Argv for the full suite, as a list of non-empty strings. `[]` skips verification. |
| `verify_timeout` | `1800` | Seconds the full suite may run. A whole number, at least 1. |
| `verify_keep` | `["target/"]` | Relative paths the scratch worktree reset keeps. |
| `batch_cap` | `8` | Most queued entries landed in one batch. At least 1. |
| `rebuild_cap` | `3` | Times a batch is rebuilt after the branch tip moves. At least 0. |
| `check` | `[]` | Argv for the fast-tier test command; changed and mirror test paths are appended. |
| `lint` | `[]` | Argv for the fast-tier lint command; changed files are appended. |
| `lint_files` | `[]` | Globs a changed file must match to be handed to `lint`. `[]` hands it every changed file. |
| `check_retries` | `1` | Times a worker is asked to fix a failed fast-tier check. At least 0. |

Both merge knobs ride lain's own command line and never your `git config`. A worker's merge should
not depend on the machine it ran on, and it must not rewrite a setting the human chose for their own
checkout. `rerere.enabled=false` is pinned on the same line for the same reason.

```ruby
isolation retain_days: 14, rebase_retries: 3
```

Landing through the coordinator adds a verify command and a batch size:

```ruby
isolation verify: ["bundle", "exec", "rake", "spec"], batch_cap: 4, verify_timeout: 900,
          check: ["bundle", "exec", "rspec"], lint: ["bundle", "exec", "rubocop"], lint_files: ["**/*.rb"]
```

A bad value is refused at `.lain/config.rb:LINE`, naming the key and what would have been legal:
`retain_days: 0 is not a whole number of days, at least 1`.

### sensitivity

`denied:`, `gated:` and `exempt:`, each a list of path globs, and `related:`, a
list of directories (each starting with `~/` or `/`, and each must exist).

* A read under a related directory masks its flagged regions without asking and never releases
  them. A file the path rules gate or deny is still gated or denied.
* The verb refuses `/`, your home directory and any ancestor of it, an entry that is not a
  directory, and a path that is not clean.
* A spawned child's read of a path outside the project root, outside every `related` directory
  and outside its own working root is gated as `outside_project`. The tools are `read_file`,
  `list_files`, `glob` (its walk root too), `grep`, `ast_search` and `file_symbols`.
  * Under `ask` it parks for the human.
  * Under `auto` the judge decides it first, and a call it is unsure of parks.
  * Under `bypass` it is approved like any gated call.
  * A child that can never park (an approval judge, the epic adjudicator) is refused.
  * The main agent's reads are unchanged.
* A `related` directory is in a child's scope as a tree: the directory itself, which a
  `list_files`, `glob` or `grep` walk names as its root, is in scope as well as every file under
  it (masking still treats the directory itself as no file).
* Known gaps, by ruling: a `grep` over the project follows a file link that points outside
  without parking, and in a chat with no project marker the root is the cwd, so a chat started
  in $HOME confines its children to all of $HOME.
* Detected secret regions are masked in what `read_file`, `grep` and `ast_search` return. A
  `grep` or `ast_search` row reads `<redacted:N>` in place with nothing parked, and a trailer
  says `read_file` on the file asks for their release. A secret path is withheld from those
  rows and is not masked.
* A name names a secret when it holds `pass`, `passwd`, `passcode`, `token`, `private` or `auth`
  as its own word (`vault-pass.txt`, `dbToken.txt`), `api key` or `api_keys`, or ends in
  `secret`, `password`, `credential` or `apikey` (`mysecrets.txt`). `AUTHORS` and
  `tokenizer.json` are ordinary, and source and markdown files are excepted by extension.
* `dbPasswordFile.txt` is a known miss and `libsecret` a known catch. A bare `pass` also gates
  compiler-pass files such as `*_pass.mlir` and `hlo/pass/`, by ruling.
* A directory named so counts below the project root and below a checkout.

### shell

`exclude:` is a list of program names or globs the shell tool refuses. `exclude: %w[*]` is
the strictest setting.

### search

How `grep`, `glob`, `list_files` and `ast_search` walk the project. Searches list files
the way `git ls-files --exclude-standard` does, so they skip what git's ignore rules exclude.

- `include:` is a list of globs, relative to the repository top, that name ignored files a
  search should still read. A glob that leaves the project is refused.
- `max_entries:` (20,000 by default) caps the files one walk lists, and `max_bytes:` (200 MiB by
  default) caps the bytes it reads. Both are positive integers, and a search that hits one says
  it was cut short.

### tests

A target project's test layout: where its source lives, where each level of test goes, and what is
exempt. It holds lain's own writes, and its subagents', to the layout a project already
keeps.

Enforcement is opt-in. A project with no `tests` verb is refused nothing: the layout
resolves to `TestLayout::None`, no write is ever refused for its path, and the session journals a
single `test_layout_absent` record to say the guard ran with nothing to enforce. Nothing is
auto-detected on your behalf, deliberately: a detected preset would impose level roots on a project
that never chose them and start refusing its existing flat specs as strays.

| Key | Default | What it does |
|---|---|---|
| `preset` | none, required once the table exists | `rspec`, `minitest`, `pytest`, or `cargo`. Sets every key below, and names the test-file shape (`_spec.rb`, `_test.rb`, a `test_` prefix, `.rs`). |
| `source_roots` | the preset's: `lib` under `rspec` | The roots a test mirrors. Non-empty, relative, and non-overlapping. |
| `level_roots` | the preset's: `spec/unit`, `spec/seam`, `spec/integration` under `rspec` | Level name to its root. A level name is lowercase; roots may not nest. `cargo` maps `unit` to `inline`, which only a preset that does not mirror may use. |
| `exempt` | the preset's, which is always empty | Globs no refusal applies to. A preset exempts nothing by design; an exemption is a project's own decision to state. |
| `default_level` | unset: `unit` wherever the table declares that level, or the only level that mirrors | Where a test that names no level belongs: what the guard holds an untagged test to, and where `/implement-epic` writes an issue's failing tests. Must name a level the table declares. Required only when the table mirrors 2 or more levels and none is `unit`, which is otherwise refused rather than settled by whichever key was typed first. |
| `timeout` | `300` | Seconds a suite run may take before it is stopped and refused with a timeout error. A number above 0. |

```ruby
tests preset: :rspec, source_roots: %w[lib app], exempt: %w[spec/fixtures/**]
```

Omitted keys inherit the preset's, so the table above changes the source roots and the exemptions
and keeps `rspec`'s level roots. A `tests` verb naming no `preset` is refused, listing the 4.

### env

`env pass:` is a list of variable names. Each named variable, taken from the environment lain started
under, reaches every command the bash tool runs.

```ruby
env pass: %w[DATABASE_URL RAILS_ENV]
```

The check reads the name and never the value. A name that matches the secret shape, a name every child
has deleted whatever the list says, and a string that is not a variable name (letters, digits and
underscores, not starting with a digit) are each refused. `DATABASE_URL` passes and can carry a
password inside its value, so passing a name is your decision about what that value holds.

### todos

`todos file: "CHORES.md"` names the chore file in the project root. The value is a bare file name, with
no directory; without the verb it is `TODOS.md`. Anything else is refused by name with the file and line.

### think

`think "low"` names the reasoning level a chat asks for. The value is a non-blank string. Whether the
model accepts the level is the server's to say, so lain checks only the shape.

### review

`review model: "name"` is the model a document review runs under when it should not be the author's. The
value is a non-blank string. Without the verb a review runs under the author's model.

### budget

`budget iterations: { "plan-epic" => 80 }` replaces the default row of that name. A row is keyed by a skill, a role or `default`,
and an unknown name is refused, listing the known ones.

| Row | Default |
|---|---|
| `default` | 25 |
| `researcher` | 60 |
| `issue_orchestrator` | 200 |
| `plan-epic` | 60 |
| `create-epic-issues`, `iterate-epic`, `implement-epic` | `{ base: 25, per_issue: 3 }` |

A row is a whole number of iterations, above 0, or a hash with a positive `base` and a `per_issue` figure
for the skills whose work grows with the epic they drive.

### middleware

Your own code, run around what lain already does. The `middleware` verb takes one line per
registration, and the area (`model`, `tool`, `turn`, `repl` or `http`) is the verb of that line.

```ruby
class TagRequests < Lain::Middleware::Base
  def initialize(tag:) = (@tag = tag)
  def call(env, &app) = downstream(env.merge(tag: @tag), &app)
end

class CountTurns < Lain::Middleware::Base
  def call(env, &app) = downstream(env, &app)
end

class AddHeader < Faraday::Middleware
  def initialize(app, name, value)
    super(app)
    @name = name
    @value = value
  end

  def call(env)
    env.request_headers[@name] = @value
    @app.call(env)
  end
end

middleware do
  model TagRequests, tag: "home"
  tool { |env, &downstream| downstream.call(env) }
  turn CountTurns
  repl { |env, &downstream| downstream.call(env) }
  http AddHeader, "x-mine", "yes"
end
```

Write `Lain::Middleware::Base` in full. The file is evaluated as a string, so a bare
`Middleware::Base` does not resolve. A class defined in the file belongs to that evaluation, and a
block becomes a middleware of its own (`Lain::Middleware::Inline`).

| Area | Runs around | `env` in | Pass on, and set |
|---|---|---|---|
| `model` | each provider call | `:request`, `:stands_on` | `:response` |
| `tool` | each tool call | `:effect`, `:context`, `:tool` | `:result` |
| `turn` | each pass of the agent loop | `:iteration`, `:timeline` | `:response`, `:settled` |
| `repl` | each line a human types | `:text`, `:agent` | `:response` |
| `http` | each HTTP attempt | a Faraday request env | the Faraday response |

`env` is read-only: `env.merge(key: value)` returns a new one, and an absent key raises
`KeyError`. A middleware that answers without calling downstream must still set the key its phase
reads on the way out, or the phase raises. A `turn` class must also answer `#settle(timeline)`,
which every turn sends as it commits; `Lain::Middleware::Base` answers it with nothing to do, and
a class that does not is refused when the file loads.

Order. Configured middleware runs outermost in every phase: your user-level file first, then
the project's, each in the order written, ahead of every member lain builds. In the `tool` phase
each of lain's guards therefore judges whatever your middleware passes on, and on the way back your
middleware sees a result after `RedactSecretReads` has masked it. The approval gate stays last, so
nothing you write can sit between a judged call and its interpreter. In `http`, entries sit after
stall protection and before JSON encoding, so each retry attempt passes through them and they see
the body as a Hash.

Instances. A `model`, `tool`, `turn` or `repl` registration is a recipe: lain builds a new
instance each time it builds a stack, so 2 agents never share one. Its arguments are frozen
when the file loads, and a value that cannot be frozen is refused. `http` is the exception.
Faraday builds an `http` middleware once per provider connection, and subagents use their
parent's provider, so one instance serves the parent and every child at the same time. It must
be thread-safe. An `http` entry is a class, never a block, and faraday-retry hands the same body
object to each attempt, so an edit made in place repeats on every retry.

Refusals. A registration that is not a class (or a block), a class with no instance `#call`, a
`turn` class with no `#settle`, an `http` block, an unknown area, and a constructor that rejects
its arguments are each refused naming `config.rb:LINE` of the line that registered it.

Scope. `lain chat` and `lain up` read the middleware once, before the session opens, and apply
it to the chat and to every subagent it spawns. `lain consolidate`, `lain improve`
and `lain epic submit` read none.

The user-level file may also declare `middleware`; see [User config](#user-config).

#### Slow middleware

The whole loop runs on one `async` reactor, on one OS thread. Middleware runs inside the fiber
doing the work. A fiber yields only at an IO boundary the scheduler controls, which is what makes
the parallel-tool fan-out safe without a single lock. It is also the constraint on what you may put
in a middleware.

A middleware that does not yield stalls everything: sibling tool fibers, the compaction
summarizer, and the fiber draining the `Channel` to the frontend. The symptom is a frozen HUD, a
`lain watch` window that stops updating, and a tool fan-out that quietly serializes. Three things
cause it:

- a tight CPU loop (a big regex over a whole file, a JSON round trip of a huge result),
- an FFI or native call that blocks without the fiber scheduler's hooks,
- blocking IO not routed through a scheduler-aware call.

Shelling out is not one of them. Ruby's fiber scheduler hooks `Lain::Shell::Out`'s `IO.select` and
`Process.waitpid2`, measured under a 10MB stdout flood, so `bash` runs as an ordinary task.

No middleware here can interrupt what runs inside it. Interrupting arbitrary Ruby would need a
watchdog thread, which the no-threads constraint rules out, so a middleware wanting to bound how
long a downstream takes can only publish a value into `env` (a monotonic deadline, say) for a
cooperative downstream to honor, and check afterward whether it was. That bounds reporting and never
execution. A middleware that hangs is not stopped by any of this, and `/quit` or Ctrl-C cannot stop
it either, since cancellation lands only at the next scheduler yield point.

So: keep middleware cheap and non-blocking, and route IO through async-aware calls. The fiber
posture and its measurements are in [`docs/devs/concurrency.md`](../devs/concurrency.md).

### github

`github account: "your-login", orgs: %w[your-org], roots: %w[~/src], keywords: %w[perf sql], paths: [%r{\Adb/migrate/}], since_days: 14`
sets the GitHub account lain's `gh` calls act as, and the filters the review queue uses. Either the user's
config.rb or a project's may say it. `LAIN_GH_ACCOUNT` in the environment beats the project, which beats the user,
field by field. Unset, the account is `gh`'s own and `since_days` is 14. An unknown key, or a value of the wrong
type, is refused by name.

## User config

`$XDG_CONFIG_HOME/lain/config.rb` (by default `~/.config/lain/config.rb`) applies to every project. It
accepts only the verbs below. A project-only verb in it is refused, as a user-only verb is refused in a
project's file.

It runs only after `lain trust --user`, which shows the file and records its exact bytes. Trust is consent to bytes
someone reviewed: it is not containment, and an agent that can write the file can also write the
mark, as it can for a project today. Any changed byte asks again.

| Verb | What it sets | File |
|---|---|---|
| [`keys`](#keys) | Which key does what at the prompt. | user |
| [`theme`](#theme) | The styles the terminal paints with. | user |
| [`attention`](#attention) | How long an agent waits before lain notifies you. | user |
| [`remote`](#remote) | The phone's approval surface. | user |
| [`middleware`](#middleware) | Your own code, run around what lain does. | project and user |
| [`github`](#github) | The GitHub account and the review queue's filters. | project and user |

### keys

`keys approval_cycle:` names the [approval cycle key](commands.md#cycling-approval-from-the-keyboard).
It accepts only `"S-Tab"` today: every `C-<letter>` is held by lain or by the line editor. A project's
file refuses it.

### theme

`theme token: %w[style ...]` recolours the tokens the terminal paints with. It is a verb of the user's
`$XDG_CONFIG_HOME/lain/config.rb` only, after `lain trust --user`: a colour belongs to the person's terminal
and not to a project, so a project's `.lain/config.rb` that says `theme` is refused with "theme belongs in the user's
config.rb". Each value is a list of Pastel style names (colours such as `green`, `bright_red` or `on_blue`, and
`bold`, `dim`, `italic`, `underline` and the other attributes Pastel knows); an empty list paints the token plain.
A token left out keeps its default. An unknown token or style is refused by name, with the known ones, the file
and the line. A `bright_` style falls back to its base colour on a terminal below 16 colours.

### attention

`attention delay: 30` sets how many seconds an agent must stay blocked, or finished and unseen, before lain
sends a desktop and morning-feed notice for it. It is a verb of the user's `$XDG_CONFIG_HOME/lain/config.rb`
only, after `lain trust --user`: how long to wait before interrupting belongs to the person and not to a project, so a
project's `.lain/config.rb` that says `attention` is refused naming the file, the line and the user's config.rb.
The value is a number of seconds, 0 or more, and defaults to 30. A negative or non-numeric value, or an unknown
key, is refused by name.

### remote

`relay:` and `ntfy:` set the phone's approval surface, off until `relay:` is set. It is a
verb of the user-level file only, since 1 machine has 1 phone listener: a
project's `.lain/config.rb` that says `remote` is refused, naming the user's config.rb.
[remote.md](remote.md) walks through the setup.

* `relay:` is the `"ip:port"` the relay listens on for the phone, such as `"100.64.0.1:7820"`.
  It must be loopback or this host's `tailscale0` address; `0.0.0.0` and any other
  all-addresses spelling are refused.
  * The per-user lain-daemon runs the relay as a confined worker for every chat.
  * A relay it cannot start (no matching address, an unsafe devices file) leaves the phone
    surface off. The chat says so in a `phone surface off:` line and records
    `capability_degraded`; it is never a refusal.
  * Devices are admitted with [`lain remote pair`](commands.md#lain-remote).
* `ntfy:` is an `http` or `https` topic URL, such as `"http://100.64.0.7:2586/my-lain-topic"` on
  a self-hosted server (or `"https://ntfy.sh/my-lain-topic"` on the public one;
  [remote.md](remote.md) says what that sees). Anything else is refused. It takes
  effect only with `relay:`, and the lain-daemon sends the notice, not the chat.
  * An item that waits 60 seconds unanswered sends 1 notice to the topic: a title naming the
    kind and the requester plus an Open action into the phone app
    (`lain-remote://item/<phone id>`), and no item text, token or path.
  * An item answered first never buzzes, and a chat that reconnects to the same daemon does not
    buzz an item twice.
  * A daemon restart forgets what it announced, so an item still waiting after one (an epic gate
    held across it, say) is announced once more as a reminder.
  * The daemon sends at most 30 notices per minute-long window; windows are fixed, not sliding.
    A window that had to drop some is followed by 1 summary, titled
    `lain: N more items waiting`, with no link, so a restart that re-arms a long agenda still
    tells you to open lain.
  * An https topic is verified against the system's roots as OpenSSL finds them.
    `SSL_CERT_FILE` replaces only the default file and `SSL_CERT_DIR` only the default
    directories, so a variable naming a private CA still leaves the public roots trusted (on
    macOS a set variable replaces the keychain).
  * A topic that is down writes a line to the daemon's trace,
    `$XDG_RUNTIME_DIR/lain/daemon/daemon.trace` (`/tmp/lain/daemon/daemon.trace` when
    `XDG_RUNTIME_DIR` is unset), each time its error changes. A topic that keeps failing the same
    way costs 1 line and not 1 per item.
  * A redirect from the topic is not followed and is traced as `ntfy answered 302`.
  * The launch passes `http_proxy`, `https_proxy` and `no_proxy`, in either case, to the daemon.
    The daemon's HTTP client picks the proxy as it does: `ALL_PROXY` first if it were set (the
    launch does not pass it), then `HTTPS_PROXY`, then `HTTP_PROXY`, for a topic of either
    scheme. A host named in `NO_PROXY` goes direct, an http topic is tunnelled with `CONNECT`,
    and a proxy variable that is not a valid URL is ignored, so the post goes direct.
  * The topic and the daemon's launch digest reach the daemon in its environment and never its
    command line, since any user can read a command line and a topic is as good as a password to
    anyone who can post to it. It is a shared name to ntfy, which is why nothing else rides on
    the notice.
