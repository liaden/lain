Problem: `plain` holds `c`, but commit's `-c` takes a value. So `-cm` reads as the flag `c` followed by `-m`.

**NIT (Linus).** A name holding a `"` partway through can hide a later `headers=@` from the scanner where curl still reads it. Example: `-F 'x=@a;type=t;"z;headers=@.env"'`. curl opens `.env"`, a name ending in a quote; the card names only `a`. curl is not quote-aware inside a content-type continuation, and the scanner is. Only a file whose name ends in a quote can be missed this way. Leave it unless someone plants such a file.

The other way round, the scanner reads a quoted `filename="a;headers=@.env"` as unquoted text and names `.env"`, which curl never opens. That over-names, which is safe.
