## The five findings, and what changed

**1. `:inherit` collapsed every hop to a self-address.** A correlation is a
chain's ROOT digest, and `:inherit` is `parent.fork`, so an inherit child
shares its parent's root PERMANENTLY -- meaning the child's own future
correlation and its immediate parent's are the SAME STRING, computable at
spawn time from `base` (the child's starting Timeline) before the child's own
Timeline object even exists, since a fork's root never changes as later turns
land on it. Left alone, the child's own Q would write `from:` that string and
`Chain#asking_handle` would hand the SAME string right back as `to:` -- a hop
addressing a chain to itself, and repeatable at every `:inherit` level in a
multi-hop chain.

Fixed by collapsing, not by a second addressing scheme: `Chain.escalation_road`
(now a class method on `Chain`, moved there to keep `ClassLength` honest --
see below) builds `[correlation_of(base), correlation_of(parent), *beyond]`
and collapses every RUN of equal adjacent addresses with `chunk_while`, then
drops the leading entry (always the child's own identity, never a real
address). Under `:fresh`/`sibling_template`, `correlation_of(base)` is nil (a
brand-new root has no head yet), so nothing ever collapses there -- the
ordinary case is unchanged, byte-for-byte, which is why none of the
pre-existing fresh-prefix specs moved.

Verified: all 3 of the panel's `:inherit` probes pass now (single-hop road at
both depths tested, `to: HUMAN` directly, `from != to` at the child's own Q).

**2. `Unattended::REFUSAL` told a specific false thing when used via
`NoAskers`.** The text said "(it was started with --non-interactive)" --
true for `CLI::Wiring::Askers#asker_over`'s own case, false for
`Tools::Subagent::NoAskers` (an unwired SEAM, unrelated to that flag). Rather
than reword the shared constant (which would have made the ORIGINAL, still-
accurate case wrong instead), added a second wording,
`Unattended::NO_MAILBOX`, naming the observable fact ("no human mailbox is
reachable from this agent") and saying ESCALATION rather than ask. `Unattended`
gained a `text:` constructor keyword (default: the unchanged `REFUSAL`), and
`NoAskers.enrol` passes `text: Unattended::NO_MAILBOX` explicitly. The
session-wide `--non-interactive` path (`askers.rb`, untouched) keeps getting
the original, still-accurate wording via the default.

Named `text:`, not `refusal:`: `spec/refusal_width_discipline_spec.rb` traces
dataflow into nvim's `review_refused` echo rail through any kwarg labeled
exactly `refusal` (its `SLOTS` list) -- and my FIRST attempt at this fix,
which did name it `refusal:`, tripped that spec for real: it correctly found
`NO_MAILBOX` reachable via the label and measured it at 214 columns against
an 80-column bar meant for nvim's message area, which this tool-result
refusal (read only by the model, never echoed to nvim) has nothing to do
with. Renaming the kwarg to `text:` removed the false dataflow edge; the
width-discipline suite is green again (29/29) with the constant unchanged.

Necessarily touches `lib/lain/tools/ask_human/unattended.rb`, one file
outside the originally-enumerated list -- the fix the panel asked for lives
nowhere else `Unattended` is defined.

**3. A frozen `Parent` handed out a mutable escalation road.**
`Parent#initialize` now does `@escalation = escalation.dup.freeze` (was:
`@escalation = escalation`, so `handle.escalation << "smuggled"` succeeded
despite the object's own `freeze`). Also froze `Seam`'s default
`escalation: [AskHuman::HUMAN].freeze` -- inline, not a shared top-level
constant: `AskHuman` loads AFTER `Subagent` in `lain.rb`'s manifest, so a
top-level `DEFAULT_ESCALATION = [AskHuman::HUMAN].freeze` constant (evaluated
at class-body/load time) raised `NameError: uninitialized constant
...::AskHuman` on first attempt -- caught immediately by re-running the specs,
reverted to an inline default (a default ARGUMENT expression, evaluated lazily
at `Seam.new` call time, by which point `ask_human.rb` has loaded). Verified:
the panel's frozen-road probe (`handle.escalation << "smuggled"` now raises
`FrozenError`) passes, and `Ractor.shareable?` holds for every event a relay
writes (also panel-probed, unaffected by this fix but re-verified green).

**4. The `from` fallback could name the relayer instead of the asker.**
Documented, not guarded, per the panel's "do not build machinery": a comment
on `AskHuman#emit_question` (in scope; the two callers that would need a real
fix -- `HumanReplies::InboxItem.asked` and `CLI::Wiring::Askers#desktop_name`
-- are not) names the hazard precisely: `@last_question.from` is now the LAST
relayer's identity rather than the original asker's, so a caller falling back
to the bare event's `from` when `ASKED_BY`/`agent` is blank would show the
relayer. Both production enrolment sites always pass a name today, so this
stays dormant; closing it means deciding what those two out-of-scope callers
should show instead, which the comment leaves as their call.

**5. Say it once.** The "a caller forwarding `parent:` unchanged inherits the
address" explanation now lives at `Parent#to` only; `AskHuman#initialize`'s
`to:` doc and (already, from this round's finding-1 rewrite)
`Chain#asking_handle`'s doc both just point at it instead of restating it.

## A `ClassLength` regression along the way, fixed by extraction

Finding 1's fix initially added `escalation_road` as a private instance
method on `ChildBuilder`, which pushed that class to 111/110 lines. Per
CLAUDE.md ("extract a collaborator... a tripped cop is usually telling you an
object is missing"), moved it to `Chain.escalation_road` -- a class method,
since `own_chain` needs the value BEFORE a `Chain` instance exists to call it
on -- taking exactly the three things it needs (`base`, `parent`,
`beyond: @seam.escalation`) as arguments rather than reaching for `ChildBuilder`
ivars. `rubocop lib spec bin`: clean.
