## Predicate: why not a literal `Usage#zero?` call

The card asked for `Usage#zero?` rather than a second spelling. `StatusFeed` is handed
the **journaled record** (a String-keyed Hash), never a `Usage` value, and
`lib/lain/status_feed/journaled_usage.rb` carries an explicit, spec-pinned refusal to
rebuild one here: `Usage.from_anthropic_wire` goes through `Integer()`, and a raise
inside a `CLI::JournalTee` sink costs the agent its turn
(`spec/lain/status_feed/journaled_usage_spec.rb` "a malformed record ... derives zero
from a field that is not a number rather than raising").

So the rule is spelled as `JournaledUsage#total_tokens.positive?`, which is *exactly*
`Usage#zero?` over the same four fields — `TOKEN_FIELDS` is pinned equal to
`Usage#total_tokens`'s field set by that same spec, and token counts are non-negative,
so `total_tokens.zero?` holds iff all four fields are zero. No drift surface against
T4's `Usage#zero?`; the comment names `Usage#zero?` as the rule and says why it is
spelled against the hash. Touching `journaled_usage.rb` to add a delegating `#zero?`
would have widened scope beyond the card's two files, so I did not.

Escalation trigger 3 (output billed with no input) does **not** apply: the guard is the
all-fields rule, so a turn billing output but zero input still publishes its (zero-input)
occupancy exactly as before. Only an entirely-zero record is suppressed.

# Fix round (orchestrator's APPROVE-WITH-FIXES)

All five items addressed in the same two files. No git commands run; no shared file touched.

## 1. Predicate ruled to `usage.total_input_tokens.positive?` — done

The gate moved INTO `#occupancy_of`, where it sits directly above the expression whose
numerator it guards:

```ruby
def occupancy_of(usage, model)
  return nil unless usage.total_input_tokens.positive?

  @context_window.occupancy(usage.total_input_tokens, model:).ratio
rescue ContextWindow::UnknownModel, ArgumentError
  nil
end
```

Gate and numerator are now the same three fields by construction rather than by
coincidence, and the docstring says so, names the `Ollama::Decoding#build_usage` shape,
and records that `Usage#zero?` is the FOUR-field question and therefore not the predicate
here. `.positive?` kept as the word, matching T4.

## 2. The rescue's `nil` was being assigned — root cause taken, not patched

`@occupancy` had three ad-hoc writers. It now has **one**, plus the seed:

```ruby
# `@occupancy`'s ONE writer after the seed, and the whole policy in a
# sentence: an absence never overwrites a reading. [...]
def record_occupancy(reading)
  @unmeasured_turns = reading.nil? ? @unmeasured_turns + 1 : 0
  @occupancy = reading || @occupancy
end
```

`#occupancy_of` now answers ONE question — is there a reading — for both unmeasurable
causes (nothing billed in, unresolvable model), and `#record_occupancy` answers the other
— what happens to one. `#observe_usage`'s body ends `record_occupancy(occupancy_of(usage,
event.model))`; the next writer inherits the policy for free.

I chose the single-writer method over a `Reading` / `Reading::Absent` pair. CLAUDE.md's
Null Object rule is aimed at a nil guard repeated at call sites, and after this there is
exactly one nil question in exactly one method; a value class plus a Null Object would
also have to serialize back to a bare Float-or-nil for the JSON, which puts the nil back.
`reading || @occupancy` is the policy as one expression.

**Red before green for this specifically** — the unresolvable-model example failed
`Expected nil to eq 0.25` before the change (full red block below).

## 3. Observability — new published field `unmeasured_turns`

A streak, not a total, on `derivation_refusal_streak`'s exact argument: it answers "how
stale is this ratio" and a measurable turn clears it. Chosen over `occupancy_observed_at`
because `#observed` is the change token and must not carry a clock reading — that split is
the class doc's own rule. It is derived from an event, so it lives in `#observed` (pinned),
which also means the first suppressed turn earns its own publish instead of being skipped.

Bullet added to the class doc; the `#observed` docstring extended to cover it.

Renderers are unaffected: `plugin/tmux/scripts/lain-status` and `CLI::Up::Hud` take the
keys they know, and the only place in the repo that enumerates the published key set is
`status_feed_spec.rb`'s "writes valid, complete JSON with every published field" — in
scope, updated.

## 4. Boundary pins — pinned in the MEASURES direction

Two examples added: `"input_tokens" => "250000"` and `"input_tokens" => 250_000.0` both
publish `0.25`. The comment states the asymmetry plainly — unparseable garbage reads 0
through `to_i` and therefore SUPPRESSES, while a plausible count in the wrong JSON type
still MEASURES, because a provider spelling a number as a string or a float is a wire
quirk rather than a claim about the window.

  a 6-line body. Under the `timeline.rb` bound of 24.
- The closing sentence *"This producer therefore cannot publish 0.0 at all, which is
  intended"* is **gone**, not narrowed — it was falsified by the §1 defect.
- The duplicated reasoning is now in ONE place. The code carries the mechanism; the three
  spec preambles were cut to a two-line pointer at `#record_occupancy` plus one line each

- `bin/comment-census lib/lain/status_feed.rb`: longest non-class-doc block is 21 lines
