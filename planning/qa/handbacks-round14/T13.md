**`Pool` has exactly one consumer: confirmed.** `grep -rn 'claim_index\|release_index' lib/ spec/ bin/`
found four hits and no more — the two `Provisioner` definitions and Redis's two calls. `grep -rn '\bPool\b'`

flagged as invisible to grep: `lib/lain/isolation/` has **no** `send`/`public_send`/`__send__` at all, and

selects services by `respond_to?(:provision)`, which is the only duck-typed dispatch into a service and is
unaffected.

**`Telemetry::IsolationLease` carries NO redis-shaped field.** Its attributes are
`kind`/`worker_key`/`backend`/`service`; `kind`'s inclusion validator is
`%i[acquired released service_provisioned service_torn_down]`, none of them redis-specific, and
`service` is a free String that a backend fills from `Provisioned#service_name`. Redis appeared
only in two comment sentences, which I updated (`"postgres", "redis"` → `"postgres",
"compose_cache"`, using a name `Services::Compose#name` actually produces). **No journal field was

# Fix round — orchestrator review (APPROVE-WITH-FIXES)

## §1 BLOCKER, fixed: the replacement line now works

Confirmed by execution before changing anything. Declaring the previously-advised literal through
the real DSL produced exactly what the review predicted:

```
1) hands over a replacement line that really works, yielding a URL a redis client can parse
   Failure/Error: expect(services.first.url(32_768)).to eq("redis://localhost:32768")
     Expected "tcp://localhost:32768" to eq "redis://localhost:32768".
```

`Services::Compose#scheme` defaults to `"tcp"`, so the operator would have copied the refusal
verbatim and met the failure at connect time inside their own app.

**Fix.** The advised declaration is now a named constant, `Builder::REDIS_REPLACEMENT`, carrying
`scheme: "redis"`, and the refusal interpolates it:

```ruby
REDIS_REPLACEMENT = 'compose service: "redis", container_port: 6379, ' \
                    'env_var: "REDIS_URL", scheme: "redis"'
```

A constant rather than an inline string specifically so the advice and the test of the advice
**cannot drift**: the spec declares that exact string through `Services.load` and asserts the URL
it yields. The advice is now falsifiable, which is what the review asked for.

Final message an operator sees:

```
the `redis` service was retired from .lain/services.rb; a container is the isolation route for
redis now -- put it in your compose file and declare it here as `compose service: "redis",
container_port: 6379, env_var: "REDIS_URL", scheme: "redis"`, which leases a stack per worker
with no shared DB-index and no 16-database ceiling. Known services: postgres, compose
```

**Two examples added** to `services_spec.rb` (16 → 18):

- `hands over a replacement line that really works, yielding a URL a redis client can parse` —
  loads `REDIS_REPLACEMENT` through the DSL, asserts `name == :compose_redis` and
  `url(32_768) == "redis://localhost:32768"`. This is the one that was red.
- `quotes the whole replacement declaration, so the refusal is copy-pasteable rather than a hint`
  — `a_string_including(REDIS_REPLACEMENT)` against the message, so the refusal can never quote a
  *different* line than the one proven to work.

The weak `/container.*compose|compose.*container/mi` assertion is kept (it pins the framing) but
is no longer load-bearing — the two above are.

Used `a_string_including` rather than an interpolated regexp: the regexp form tripped
`Performance/ConstantRegexp`, and the matcher reads better anyway.
