# T6 — A parked question cites an edge the record already carries

## Route taken: **flush the child's feed before the question is written**

Not "cite an already-recorded edge", and the reason is that the only edge already on
the record at that instant is the `:spawn` — citing it would have thrown away *which
turn* the child asked from, which is the whole content of the citation. Flushing keeps
the citation meaning what it says and makes it true.

It is also the shape the card pointed at: `CLI::Repl::Ask#record_interruption` does
exactly this for the parent ("catch_up FIRST … so the committed turns are journaled
before the stop is recorded"). The child had no equivalent, because the object that
promotes its turns (`Middleware::JournalTurns`) only runs when an iteration *returns*,
and a parked ask never returns from the one it was asked in.

**Re-entrancy checked (escalation trigger 2):** the flush calls `TurnFeed#catch_up`
directly, never `JournalTurns`. The feed's `@stop` advances per turn, so the catch-up
the iteration runs afterwards walks an empty range. Both calls are on the same fiber —
`ask_human` is not `parallel_safe?`, so it is a barrier and no two askers interleave —
so there is no nested or concurrent walk. Nothing re-enters the middleware.

**Not per-settle (escalation trigger 3):** feeding stays per-iteration. The flush is an
*extra* promotion on the same feed, at the one moment per-iteration is not often enough.
The comment at `recorded_turns` now says that in words.

**`to:` untouched (escalation trigger 1):** the fix is entirely at `causal_parents`
reachability. The question's address is exactly as it was; T7 owns that.

## Files changed

### `lib/lain/tools/ask_human.rb`
- New `AskHuman::Parent` — the live parent handle, normalized. It answers `#timeline`
  (a Timeline passes through, a thunk is called — the old `parent_timeline` body) and
  `#settled`, which settles the record *first* and then answers the same head. Its
  `Settled` null leg is what every non-spawn caller gets: whoever owns that record
  catches it up already. `Parent.over` is `is_a?`-based for `#announcement_for`'s
  stated reason.
- `#initialize` wraps whatever it is handed: `@parent = Parent.over(parent)`. Every
  existing call site (Timeline, thunk) is unchanged at the seam.
- `#parent_timeline` is now one delegation to the handle.
- `#emit_question` reads `@parent.settled` instead of `#parent_timeline`. That is the
  fix: one line, and the ordering is the whole of it.

### `lib/lain/tools/subagent.rb` — the enrolment site
- New `ChildBuilder::Chain` value: `(base, timeline, feed)` — one spawn's own chain.
  `#asking_handle` builds the `AskHuman::Parent` the asker is enrolled with; `#promote`
  is `feed.catch_up(timeline.call)`.
- `#build` now constructs the chain (`#own_chain`) *before* enrolling, and hands
  `chain.asking_handle` to `@seam.askers.enrol` instead of the bare thunk. This is the
  "more than a timeline thunk" the card predicted, and it had to ride the `parent`
  argument: `CLI::Wiring::Askers#enrol(parent, agent:)` forwards nothing else, and
  `askers.rb` is out of scope.
- `base_timeline` and the `TurnFeed` moved out of `#spawn_agent` into `#own_chain`,
  because the asker is enrolled before the Agent exists and needs the feed. Both are
  pure (`Timeline.empty` / `parent.fork`), so computing them earlier changes nothing.
  Built per spawn, never memoized on the builder — a fan-out runs siblings concurrently
  over one builder.
- `#spawned`/`#spawn_agent` take the chain in place of `parent` (same arity);
  `#recorded_turns` takes the chain and reuses `chain.feed` rather than making a second
  one. `#spawn_agent`'s `agent = nil` dance went away with the thunk it existed for.

### `spec/lain/tools/ask_human_spec.rb`
New `describe "the head a question cites"` — **the pin the card said did not exist**:
`last_question.causal_parents` is now asserted (it was asserted nowhere before).
Three examples: the head is the handle's live head; a settling handle is settled
*before* the Q is written (ordering, via a handle that records at settle time); a plain
thunk still reads exactly as a Timeline.

### `spec/lain/tools/subagent_spec.rb`
Extended `describe "the session record it leaves behind"`.
- `answered_journal` / `parked_journal` / `settled_journal` split out of the old
  `recorded_session`; the two pre-existing examples are unchanged and still green.
- `parked_journal` drives a **genuinely parked** run through the real path: the child
  asks, the question reaches the real arrival queue, **nobody answers**, and the fiber is
  stopped where it stands (`spawning`'s `ensure`). No record is hand-built anywhere —
  which is what makes these specs able to catch the original bug.
- `reopened(bytes)` writes the journal to a real session dir under a tmpdir `Paths` and
  yields a live `CLI::Resume`, so fork and resume are driven at the doors a human walks
  through, not at a loader call.
- New examples: the answered path forks **and** resumes (AC 4, at the door); and, parked:
  every cited digest is on the record (AC 1), it forks at its head (AC 2), it resumes
  onto that head (AC 3).

## Surprises

1. **The answered path really does depend on the human.** Before the fix the *only*
   thing that put the cited turn in the file was the tool_result returning and the
   iteration's catch-up firing. Every existing fixture answered, so the record was
   correct by accident of the fixture, not by construction. The parked shape is one
   `answered(…)` call away from the shape the suite already had, which is how it hid.
2. **`enrol` is a one-argument seam.** `CLI::Wiring::Askers#enrol(parent, agent:)`
   forwards `parent`, `observer` and `agent` to the asker and nothing else, and
   `askers.rb` was out of scope — so the extra capability *had* to ride the parent
   handle itself. That is what forced `AskHuman::Parent` to be a real object rather
   than an extra keyword, and it turned out to be the better shape anyway: the
   Timeline-or-thunk duck test that lived in `#parent_timeline` now lives in one place
   with a name on it.
3. **Hoisting `base_timeline` was free.** Every prefix strategy's `base_timeline` is
   pure, so moving it above the enrolment/attenuation guards changes nothing a spec or
   the Store can observe — a `NoCapability` refusal now computes a Timeline it discards,
   which costs a `Timeline.empty` or an O(1) fork.
4. **`#spawn_agent` lost its `agent = nil` self-reference.** It existed only so the
   middleware thunk could read `agent.timeline`; the chain carries that thunk now, so
   the method is a plain constructor call again.

**None.** `CLI::Wiring::Askers`, `Middleware::JournalTurns`, `TurnFeed` and
`Bench::Session::MessageReplay` are all untouched — the fix rides seams that already
existed. Nothing outside the four in-scope files changed.

## Fix 2 — read once, hand the value to the settler

`Parent#settled` is now `timeline.tap { |live| @settle.call(live) }`: one read, the
settler is *handed* that Timeline, and it is that Timeline's head the citation names.
`Null.call(_timeline)` takes the argument it will not use, so there is one settler duck
rather than two. `Chain#promote(live)` takes the Timeline; `Chain#settled` is the
same shape for the spawn leg. The comment says in words that the old form was true only
because `ask_human` is a barrier — a fact about the caller, not about the class.

Also tidied while in there (the "noted, not asked for" items I took): `Parent.new` is now
keyword-first (`read:`, `settle:`) and **freezes at birth**, like `Middleware::JournalTurns`.
`Chain` stays a `Data` over a live feed and a Proc, as you said — left alone.

## Fix 3 — the homograph

`Parent::Settled` → `Parent::Null`, matching `Sink::Null` / `ChainWriter::Null`.
`#settled` (the promoted Timeline) is now the only thing in the class wearing that word.

## One thing I am flagging rather than fixing

`Chain#settled` is reachable concurrently in one shape I did not close: a child that
issues **two `subagent` calls in one turn** dispatches them in parallel (`Subagent` is
`parallel_safe?`), and both read the *same* child `Chain`, so two fibers can be inside
one `TurnFeed#catch_up` if the observer yields. The blast radius is a duplicate
`@observer.call`, and `SessionRecord::Scribe#child_turn` already drops repeats by digest
with a comment saying so deliberately — so nothing is corrupted, and my "two siblings
park at once" spec covers the depth-1 version where each spawn has its own chain. Making
it structural would mean a guard inside `TurnFeed`, which is out of this card's Files.
Worth a line in whatever card owns nested spawning.
