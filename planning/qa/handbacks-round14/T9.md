## Where the allocator lives, and why it is concurrency-safe

The card suggested a per-tool allocator threaded through `#descend`. That is not
sufficient here, and the reason is `Skill::RoleSpawn#call`: it constructs a
**fresh** `Tools::Subagent` per call, over the seam it holds, and passes no
constructor keyword this card could add (`role_spawn.rb` is out of scope). Two
concurrent role spawns would each start a private counter at 1 and ask one
backend for the same worker id — and `Isolation::Worktree` keys its checkout
path on that id, so the second is a `Refused` at best and a clobbered live
checkout at worst. A per-tool counter has the same hole for nesting: the
grandchild's tool is a different object from its parent's.

So the sequence rides the ONE thing every tool in a run already shares — the
`Seam` — as part of the `isolation:` member's value:

- `Leases` owns the backend AND the counter. One per seam, which is one per run.
- A nested tool is a `#descend` copy built from `Seam#with`, so parent, child and
  grandchild draw from the same sequence with no new keyword anywhere.
- `#next_number` is `@monitor.synchronize { @count += 1 }`. `#fan_out` really does
  put two fibers inside it at once, and `+= 1` is a read and a write with a
  suspension point available between them.
- Ids are `"<role>-spawn-<n>"`. The `-spawn-` is load-bearing: `Supervisor`
  allocates `"<role>-<n>"` off its own sequence over its own backend instance for
  an ADOPTED actor. Two sequences that cannot see each other must not be able to
  name one path — a `Worktree` reap of a path a live sibling holds destroys that
  sibling's checkout.

The actor path is untouched: `#launch_actor` still takes the `WorkerEnv` that
`Supervisor#adopt` leased, and does not come through `#leased`. Nothing double-leases.
The backend is journalled exactly once, by `IsolationBackend` itself, nearest the
concrete; `Leases` adds no journalling.

## How scenario 1 avoids a double

`spec/lain/cli/wiring_spec.rb`, inside the existing "the fleet's isolation
backend / with the worktree isolation option" group, new context "when the MODEL
dispatches a subagent". Nothing in it is doubled or injected:

- the backend is whatever `--isolation worktree` really resolves through
  `CLI::Wiring` (a real `Isolation::Worktree` over a throwaway seeded repo and a
  throwaway `XDG_RUNTIME_DIR`);
- the tool is the one this run's own `ToolsetBuild` built;
- the spawn is a `tool_use` the model dispatched through the parent Agent's own
  loop (`Sync { agent.ask("look around") }`), not `#run` and not a hand-rolled worker.

A child's cwd is unobservable from outside a spawn that hands back a Timeline and
never an Agent, so the child's scripted second move is `list_files` at the
RELATIVE path `no-such-dir`; `ListFiles` names the absolute path it resolved to in
the refusal, and the spec reads that back off the mock provider's recorded requests.

## 2. The reclaim tolerance

`Isolation::Worktree#remove` raises `Refused` deliberately, and `Tool#call` does
not rescue — so a bare `ensure lease&.release` handed the parent a teardown
failure in place of a completed child's answer.

The whole lease lifetime moved onto `Leases#hold(role, journal:)`, which mints,
acquires, yields, and gives back through a private `#reclaim` carrying
`Supervisor#reap`'s tolerance: attempt it, then let the record say what happened.
`Subagent#run_child` is now one call and `#leased` is gone.

The failure is journaled, never swallowed — a checkout that outlived its lease is
a real leak and `worker_key` is how someone finds it. New tool-local record
`Subagent::LeaseNotReclaimed`, on `Stagger::Dispatched`'s precedent (a `Data`
with `Telemetry::Journalable`, pushed onto the tool's own journal). The journal
is the SEAM's, read through the same delegator every other record on this path
uses, so the lease lifecycle cannot write to a channel the spawn did not.

RED: `Lain::Error: could not reclaim /…/subagent-spawn-1` escaping the dispatch.
GREEN: the result is `ok`, its content is `"child answer"`, and the leak record
names the worker.

## 3. `Isolation::WorkerId` — the object both allocators draw from

New `lib/lain/isolation/worker_id.rb` (+ index line in `lib/lain/isolation.rb`,
+ `spec/lain/isolation/worker_id_spec.rb`). Both allocators now mint through it:
`Supervisor#next_worker_id` in the `adopted` lane, `Leases#hold` in the `spawned`
lane.

Disjointness is the object's own property, not a convention two call sites share.
An adopted id always ends in a hyphen and its ordinal; a spawned id puts
`-spawn.` in front of the ordinal, so the character before its digit run is never
a hyphen and **no role name can forge the other lane**. The old spellings could
not promise that: adopted `"reviewer-spawn"` at 1 and spawned `"reviewer"` at 1
read identically. The spec proves it over adversarial role names
(`"reviewer-spawn"`, `"reviewer-spawn.1"`, `"reviewer-1"`, `""`) rather than by
example.

**The adopted spelling is byte-identical to today's**, so `supervisor_spec`'s
`"researcher-1"` / `"worker-1"` assertions and every journalled `worker_key` are
unchanged. `supervisor.rb`'s change is three lines and the widening beyond the
card's file list is `supervisor.rb` + the two new files; I judged that
unavoidable for "both allocators", and flag it rather than assume it.

I also added a direct contention example on `Leases`: 64 concurrent `hold`s,
64 distinct ids. That is a stand-in for the panel's own concurrency probe, which
can no longer run as written — see below.

## 1. `fleet_isolation` takes no argument

Agreed without reservation — a memo that honours `journal:` once and discards it
forever was the fourth convention-plus-comment in a round spent removing three.

- `Wiring#wire_agent` assigns the run's Channel to a slot, `@channel`, on
  `@agent`'s own written rationale.
- `#fleet_isolation` is argument-free and reads it.
- `#build_toolset` lost its `journal:` parameter and reads the slot too.
- `#run` no longer keeps a `channel` local: it builds the Channel straight into
  `wire_agent`, and the two later reads go through the slot.

**One thing the ruling did not anticipate, and my call on it.** `#build_toolset`
is private but two specs drive it through `send` without ever calling
`#wire_agent` — `spec/lain/cli_spec.rb:175` and
`spec/lain/cli/wiring/agent_build_spec.rb:479`. Dropping the parameter left them
passing `journal:` to a method that no longer takes it (3 red), and simply
deleting the argument would have left `@channel` nil for a collaborator to push
records onto. So the slot is read through a Null-defaulted reader:

```ruby
def channel = @channel || Lain::Channel::Null.instance
```

which is the codebase's own Null-Object-over-nil rule rather than a nil landmine,
and I dropped `journal:` from those two call sites. That is a third widening
beyond the card's file list (two spec files, one argument each) and it was forced
by the ruling rather than chosen.

**The ClassLength budget came out even, so `#quiescent?` did not have to pay for
it after all** — but you accepted it and reverting would cost two lines I do not
have, so it stands. The ledger: `@channel` slot +1, Null reader +1, `def root =
project.root` +1 (which is what lets the memo fit inside 120 columns as a

## 2. The 64-way example now tests what it claims

already-leased refusal is armed the whole time. The comment now says why the park

high-water mark is one.

Green on first run, as expected — the implementation was already correct; it was
the claim that was not.
