# cockpit_deny re-record: why it timed out

## Cause

The model was fine, and the wait in the journey was the problem.

In the T11 record run, ollama got 2 `/api/chat` calls, the same shape as main's cassette:
1. A `bash` call, which the human denied.
2. A plain-text final answer.

The model made no `epic_*` call and did not loop. The turn ended (`end_turn`), the approvals
count went back to 0 and `you>` came back. Only the last wait failed: "the final reply drawn
in the chat pane".

The chat pane, as captured:

    The command `touch made-by-agent.txt` was refused by the system. Per your instruction, no further attempts wi
    ll be made.

The pane is 110 columns wide and wraps hard in the middle of a word. `reply_drawn?` squished
the capture to "... wi ll be made." and looked for the reply's last 3 words, "will be made.",
so it could never match.

Whether a word in the last 3 straddles the wrap column depends on the exact wording. Adding a
tool changes the request, which changes the qwen3:4b reply. That is why T10 passed on its 3rd
try (other wordings) and why T11 hit the split word every time. With these settings the model
gives the same answer each time. The journey can be recorded with this tool list; the check
just has to ignore line wraps.

## Fix (spec only)

File: `spec/e2e/cockpit_approval_spec.rb`.

`drawn?(chat, text)` takes every space and line break out of both sides before it matches.
`reply_drawn?` and the approve example's "shows the model's final reply" assertion both use
it. Before, that assertion used the same squish check, so it had the same latent flaw.

## Result

- Failing run, before the fix (it overlapped a landing hook, but the pane capture shows the
  cause on its own): "the final reply drawn in the chat pane never held within 300s".
- Record run after the fix, with no hook running: 2 examples, 0 failures in 20s. The new
  `spec/fixtures/vcr_cassettes/e2e/cockpit_deny.yml` has 2 interactions, and its tool list
  includes `epic_graph`. `probes.yml` was kept.
- Offline replay of the whole journey file, approve and deny: 6 examples, 0 failures.
- rubocop on the spec file: no offenses.

Files changed:
- `spec/e2e/cockpit_approval_spec.rb`
- `spec/fixtures/vcr_cassettes/e2e/cockpit_deny.yml` (re-recorded)

Process note: the hook wait pattern `pre_commit hook-impl|[p]re-commit run` matches its own
shell command line when it is passed inline to `pgrep -f`, so the wait never ends. Put it in a
script, or bracket the first letter of both halves:
`[p]re_commit hook-impl|[p]re-commit run`.
